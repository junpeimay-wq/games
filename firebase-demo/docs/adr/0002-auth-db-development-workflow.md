# ADR-0002: 認証・データベース機能の先行実装とテスト

## ステータス
承認済み

## 日付
2026-10-03

## コンテキスト
認証やデータベース機能を各ゲームへ個別に追加すると、設計・セキュリティルール・データ形式・エラー処理がゲームごとにばらつき、テストされない変更が配信されるおそれがある。`firebase-demo` にはFirebase AuthenticationとFirestoreを使った共有機能、およびFirestore Emulatorでルールを検証するテスト基盤がある。

## 決定
- 認証またはデータベースに関する新機能・仕様変更は、各ゲームへ展開する前に `firebase-demo` で先行実装する。
- 先行実装には、利用する認証・DBの動作、セキュリティルール、データ形式、成功・拒否ケースを確認する自動テストを含める。Firestoreルールの変更はFirestore Emulatorで検証する。
- `firebase-demo` の関連テストが通ることを確認してから、各ゲームに機能を展開する。ゲーム固有の挙動に関するテストも追加・実行する。
- 先行実装からテストまでを独立して完了できない場合は、各ゲームへの展開を保留し、未検証の範囲とブロッカーを明記する。
- この順序とテスト要件を後続のAIエージェントを含むすべての実装者に適用する。リポジトリルートの `AGENTS.md` に作業手順を記載する。

## 理由
- 共通の実装と検証を各ゲームへ展開する前に確認でき、ゲームごとの仕様差やルール逸脱を防ぎやすい。
- Emulatorによる再現可能なテストで、Firebaseの認可ルールやデータ検証の回帰を早期に検出できる。

## トレードオフ
- 各ゲームへの展開前に `firebase-demo` の実装・テストが必要となり、初回の機能追加には時間がかかる。
- Emulatorで確認できるのは実装したテストケースの範囲であり、本番Firebase環境の設定や、クライアントから送られるゲーム結果の正当性までは保証しない。
