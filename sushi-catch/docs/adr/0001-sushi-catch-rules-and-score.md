# ADR-0001: まわるおすしキャッチの基本ルールとスコアの定義

## ステータス
承認済み

## 日付
2026-11-23

## コンテキスト
GAME ARCADEに、回転寿司をテーマにしたタイミングゲームを新しく追加する。主な対象は小学校低学年の子どもで、操作は「流れてくるお寿司がゾーンに入った瞬間に、そのレーンをタップする」だけに絞る。アーケードの他ゲームと同様に、スコアの定義とランキング連携の方法を先に定めてから実装する必要がある。テーマは2026年12月の新作として、雪合戦・サンタの配達・回転寿司キャッチの3案からオーナーが本案を選んだ。

## 決定
- `sushi-catch/` は60秒のタイミングゲームとする。3段のレーンを左から右へお寿司が流れ、右端のキャッチゾーン（中心 x=404、幅64px）に入った瞬間にそのレーンをタップするとキャッチできる。時間経過でベルトは速くなる（70px/秒から上限175px/秒）。
- 操作はタッチ（レーンの直接タップと、レーンごとの大きなボタンの両方）とキーボード（1/2/3で各レーン、↑↓＋スペースでも可）の両方に対応する。タッチUIの表示は画面幅ではなく入力手段で決める（[共通ADR-0017](../../../docs/adr/0017-touch-controls-by-input-capability.md)）。
- お寿司の種類と基本点は、たまご10点・サーモン10点・まぐろ20点・えび20点・いくら30点・大トロ100点（レア）とする。ゾーン中心から±12px以内は「ピッタリ」で+20点ボーナス。
- コンボは連続キャッチで伸び、10コンボごとに倍率が+1倍（上限5倍）になる。空振り（スカッ）か、わさび軍艦を取るとコンボはリセットされる。減点はしない（低学年向けに優しい仕様）。
- わさび軍艦はハズレ枠とする。取ると0点でコンボがリセットされ、0.8秒間キャッチできない硬直が入る。
- 金の皿のお寿司を取ると10秒間のフィーバータイムになり、全ての得点が2倍になる（コンボ倍率と重なる）。
- スコアはキャッチしたお寿司の得点の合計とする。制限時間終了でゲームオーバーとなり、もう一度遊べる。
- ランキング連携は共通基盤（`firebase-demo/score-service.js`）を使い、[共通ADR-0001](../../../docs/adr/0001-game-scores-and-rankings.md) に従う。自己ベストを更新したときだけ、認証済みなら自動記録し、未認証なら認証して記録するかを確認する（確認はセッションに1回だけ、[共通ADR-0016](../../../docs/adr/0016-ranking-sign-in-prompt-once-per-session.md)）。スコアの手入力はさせない。
- 自己ベストは端末の `localStorage` にも保存し、Googleログイン済みの場合は起動時にクラウドの自己ベストを優先して反映する（[共通ADR-0013](../../../docs/adr/0013-authenticated-score-sync.md)）。
- 判定・得点・倍率・ベルト速度・出現抽選などの純粋ロジックは `sushi-catch/logic.js` に分離し、単体テストで検証する。Firestoreの許可ゲームへの `sushi-catch` 追加はルール変更として firebase-demo のEmulatorテストで検証する（[firebase-demo ADR-0002](../../../firebase-demo/docs/adr/0002-auth-db-development-workflow.md)）。ルールのデプロイはマージ時にCIが自動で行う（[共通ADR-0018](../../../docs/adr/0018-firestore-rules-ci-deploy.md)）。
- 子ども向けの表現として、お寿司はコミカルなドット絵にし、キャッチすると星が飛ぶ演出にする。残酷な表現は入れない。

## 理由
- 「ゾーンに入った瞬間にタップ」だけの操作は低学年でも直感的に分かり、コンボとフィーバーで単調にならない。
- 空振りやハズレで減点しないことで、失敗を恐れず繰り返し遊べる。
- 共通基盤を使うことで、認証・同意確認・プロフィール同期などの挙動が他ゲームと一致し、ゲームごとに実装がばらつかない。

## トレードオフ
- スコアは出現抽選とベルト速度の調整に依存するため、バランス調整を変更すると過去の記録と単純比較できなくなる。
- クライアントから送信されるスコアは改ざん可能であり、認証とルール検証だけでは正当なプレイの証明にならない（共通ADR-0001と同じ前提）。
