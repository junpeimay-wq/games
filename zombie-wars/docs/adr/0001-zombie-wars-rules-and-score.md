# ADR-0001: ゾンビ・ウォーズの基本ルールとスコアの定義

## ステータス
承認済み

## 日付
2026-11-15

## コンテキスト
GAME ARCADEに、横視点の拠点攻防ストラテジーゲームを新しく追加する。主な対象は小学校低学年の子どもで、考える要素は「いつ・どのユニットを出すか」に絞り、ユニット同士の戦闘は自動で行う。アーケードの他ゲームと同様に、スコアの定義とランキング連携の方法を先に定めてから実装する必要がある。

## 決定
- `zombie-wars/` はプレイヤー対CPUの拠点攻防ゲームとする。左の自軍バリケードから戦士ユニットを召喚し、右のゾンビの巣のHPを0にすれば勝ち、自軍バリケードのHPが0になると負けとする。1試合は3〜5分を目安に調整する。
- コインは時間経過で貯まり（開始50、上限150、毎秒+5）、召喚コストに使う。自軍ユニットは3種類とする。
  - ナイフ戦士（20コイン）: 安い・速い・近距離。
  - 盾の戦士（45コイン）: 遅い・高HPの壁役・近距離。
  - 銃の戦士（70コイン）: 高い・遠距離攻撃（弾を撃つ）・近づかれると弱い。
  盾とナイフが前線を支え、銃が後方から撃つ編成を勝ち筋とし、銃だけの量産ではゾンビの群れに崩れるバランスにする。ゾンビの巣は硬くて弾が効かず、巣にダメージを与えられるのは近距離攻撃だけとする（銃はあくまでゾンビへの支援射撃役で、銃だけでは試合に勝てない）。
- 敵はゾンビの巣からウェーブごとにまとまって出現し、ウェーブの間には休止時間があるウェーブ方式とする。時間経過でウェーブの規模が大きくなり、ゾンビの体力も増える。休止時間に前線を押し上げて巣を攻撃するのが攻略の軸になる（連続出現だと巣の前でゾンビが途切れず、巣にダメージが入らなくなるため）。また、巣の近くに戦士が迫っていて周りのゾンビが少ない場合は、巣から防衛のゾンビが湧き出てくる（巣の前への居座り対策）。種類は通常（ふつうゾンビ）、高速・低HP（はやいゾンビ、30秒以降）、大型・高HP高攻撃（おおゾンビ、90秒以降）の3種類。
- 近距離攻撃は、攻撃対象のすぐそば（前後10px以内）に密集している敵にも当たる（巻き込み）。ゾンビは群れで密集するため、巻き込みが無いと前線が1体ずつの処理になって押し込めなくなる。
- 戦士の攻撃力はウェーブを重ねるごとに少しずつ上がる（1ウェーブごとに+6%）。ゾンビ側の強化だけだと前線が膠着して押し込めないため、長引くほど自軍が有利になる調整を入れる。
- 必殺技ゲージはレトロ格闘ファイトと同じ方式で、攻撃を当てる・ゾンビを倒す・ダメージを受けることで貯まる。満タンで「一斉射撃」を発動でき、画面内の全ゾンビに大きなダメージを与える（キー H / スペース、または必殺ボタン）。群れを崩して前線を押し上げる起点になる。
- 操作はキーボード（1/2/3で召喚、H/スペースで必殺）とタッチボタンの両方に対応する。タッチUIの表示は画面幅ではなく入力手段で決める（[共通ADR-0017](../../../docs/adr/0017-touch-controls-by-input-capability.md)）。
- スコアは「倒したゾンビ数 + 勝利ボーナス」とする。勝利ボーナスは自軍バリケードの残りHPと、早く勝つほど大きい時間ボーナス（300秒から経過秒を引いた残り、下限0）の合計。敗北時は倒した数のみ。
- ランキング連携は共通基盤（`firebase-demo/score-service.js`）を使い、[共通ADR-0001](../../../docs/adr/0001-game-scores-and-rankings.md) に従う。自己ベストを更新したときだけ、認証済みなら自動記録し、未認証なら認証して記録するかを確認する（確認はセッションに1回だけ、[共通ADR-0016](../../../docs/adr/0016-ranking-sign-in-prompt-once-per-session.md)）。スコアの手入力はさせない。
- 自己ベストは端末の `localStorage` にも保存し、Googleログイン済みの場合は起動時にクラウドの自己ベストを優先して反映する（[共通ADR-0013](../../../docs/adr/0013-authenticated-score-sync.md)）。
- 経済・ターゲット解決・ウェーブ生成・ゲージ・スコア計算などの純粋ロジックは `zombie-wars/logic.js` に分離し、単体テストで検証する。Firestoreの許可ゲームへの `zombie-wars` 追加はルール変更として firebase-demo のEmulatorテストで検証する（[firebase-demo ADR-0002](../../../firebase-demo/docs/adr/0002-auth-db-development-workflow.md)）。ルールのデプロイはマージ時にCIが自動で行う（[共通ADR-0018](../../../docs/adr/0018-firestore-rules-ci-deploy.md)）。
- 子ども向けの表現として、ゾンビはコミカルなドット絵にし、倒れると星になって消える演出にする。血や残酷な表現は入れない。

## 理由
- 拠点攻防型は「ユニットを選んで出す」判断だけに集中でき、低学年でも戦略らしさを味わえる。自動戦闘にすることで操作の忙しさに左右されず、編成の工夫が勝敗に直結する。
- 近距離（ナイフ・盾）と遠距離（銃）の役割分担を明確にすると、編成を変える楽しさが生まれる。銃だけでは勝てないバランスにすることで、3種類すべてに出番を作る。
- 共通基盤を使うことで、認証・同意確認・プロフィール同期などの挙動が他ゲームと一致し、ゲームごとに実装がばらつかない。

## トレードオフ
- スコアはゾンビの出現ペース（ウェーブ調整）に依存するため、バランス調整を変更すると過去の記録と単純比較できなくなる。
- クライアントから送信されるスコアは改ざん可能であり、認証とルール検証だけでは正当なプレイの証明にならない（共通ADR-0001と同じ前提）。
