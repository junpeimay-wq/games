# ADR-0001: コースづくりレースの基本ルールとスコアの定義

## ステータス
承認済み

## 日付
2026-11-25

## コンテキスト
GAME ARCADEに、「自分で作る系」のゲームを新しく追加する。主な対象は小学校低学年の子どもで、操作は「マス目にみちを描く」ことに絞り、車の運転は自動にする。2027年1月の新作として、オーナーが「おすし職人／ドット絵おえかき／コース作りレース／モンスター作り」の4案から本案を選んだ。アーケードの他ゲームと同様に、スコアの定義とランキング連携の方法を先に定めてから実装する必要がある。

## 決定
- `course-race/` は12×8マスのコース作成＋自動運転レースゲームとする。スタートからゴールまで「みち」を描いてつなぎ、GOで車が自動で走る。みちがつながっていない場合は出発せず、その旨を表示する（罰則なし）。
- 置けるものは、みち・⭐スター・🚀ブーストと消しゴムとする。スターとブーストはみちの上にだけ置け、再度押すと外れる。車はスターを取ると+100点相当、ブーストに乗ると1.2秒間加速する。
- モードは2つとする。
  - チャレンジ: 木・岩の障害物の配置が決まった3コース。全員が同じ条件で遊べるため、ランキングの対象とする。障害物とスタート・ゴールは消せない。
  - フリー: 障害物なしで自由に作れる。作ったコースは端末の `localStorage` に6つまで保存でき、呼び出して走らせられる。フリーモードのスコアはランキングに入らない。
- スコアはコースごとに「ゴール500点＋スター100点ずつ−時間ペナルティ（経過秒×5点、最大400点）」、下限100点とする。ランキングのスコアは3コースそれぞれのベストスコアの合計とし、コース単位で何度でも挑戦して合計を伸ばせる。
- 編集モードでは、スタートからゴールまでの最短路が見つかれば白い点でルートを表示し、子どもが「つながった」ことを確認できるようにする。車の経路も同じ最短路を使う。
- 操作はタッチ／マウス（なぞって描く）とキーボード（1〜4で道具、Enter／スペースでGO）の両方に対応する。タッチUIの表示は画面幅ではなく入力手段で決める（[共通ADR-0017](../../../docs/adr/0017-touch-controls-by-input-capability.md)）。
- ランキング連携は共通基盤（`firebase-demo/score-service.js`）を使い、[共通ADR-0001](../../../docs/adr/0001-game-scores-and-rankings.md) に従う。自己ベスト（合計）を更新したときだけ、認証済みなら自動記録し、未認証なら認証して記録するかを確認する（確認はセッションに1回だけ、[共通ADR-0016](../../../docs/adr/0016-ranking-sign-in-prompt-once-per-session.md)）。スコアの手入力はさせない。
- 自己ベストは端末の `localStorage` にも保存し、Googleログイン済みの場合は起動時にクラウドの自己ベストを優先して反映する（[共通ADR-0013](../../../docs/adr/0013-authenticated-score-sync.md)）。
- 経路探索・道具の適用・スコア計算・保存形式などの純粋ロジックは `course-race/logic.js` に分離し、単体テストで検証する。Firestoreの許可ゲームへの `course-race` 追加はルール変更として firebase-demo のEmulatorテストで検証する（[firebase-demo ADR-0002](../../../firebase-demo/docs/adr/0002-auth-db-development-workflow.md)）。ルールのデプロイはマージ時にCIが自動で行う（[共通ADR-0018](../../../docs/adr/0018-firestore-rules-ci-deploy.md)）。
- 子ども向けの表現として、車や障害物はコミカルなドット絵にし、ゴール時は紙吹雪で祝う。失敗しても怒られない表現にする。

## 理由
- 「作る→走らせる」の繰り返しは低学年でも試行錯誤を楽しめ、運転操作の難しさに左右されない。
- 自作コースは人によって条件が違うためランキングに適さない。配置固定のチャレンジをランキング対象に分けることで、公平さと自由な創作の両方を保てる。
- コース単位のベスト合計にすると、1コースずつ少しずつ合計を伸ばす遊び方ができ、短い時間でも進捗を感じられる。
- 共通基盤を使うことで、認証・同意確認・プロフィール同期などの挙動が他ゲームと一致し、ゲームごとに実装がばらつかない。

## トレードオフ
- スコアは障害物配置と時間ペナルティの調整に依存するため、バランス調整を変更すると過去の記録と単純比較できなくなる。
- 保存できるコースは端末ローカルのみで、他の端末や他のプレイヤーとは共有できない。共有ギャラリーは新しいデータベース機能になるため、必要になったら firebase-demo で先に検証してから追加する（ADR-0002）。
- クライアントから送信されるスコアは改ざん可能であり、認証とルール検証だけでは正当なプレイの証明にならない（共通ADR-0001と同じ前提）。
