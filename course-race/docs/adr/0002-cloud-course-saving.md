# ADR-0002: 保存コースのクラウド保存（Googleログイン時）

## ステータス
承認済み

## 日付
2026-11-25

## コンテキスト
ADR-0001 では、作ったコースの保存は端末の `localStorage` のみとし、クラウド保存は「新しいデータベース機能になるため、必要になったら firebase-demo で先に検証してから追加する」としていた。オーナーから、端末保存だけでなく Google アカウントと連携している場合は Firebase にも保存できるようにしたい、との要望があった。

## 決定
- 保存コースは `users/{uid}/courseRace/courses` の1文書に、名前とグリッド文字列のリスト（最大6件）として保存する。本人だけが読み書きできる。
- 機能は共通基盤側に実装する。検証は `firebase-demo/score-utils.js` の `isValidCourseRaceCourses`（純粋関数、単体テストあり）、読み書きは `firebase-demo/score-service.js` の `loadCourseRaceCourses` / `saveCourseRaceCourses` が担う。
- Firestore ルールは文書の形式（キー・件数・名前とグリッドの長さ）を検証し、未認証・他人・形式不正の書き込みを拒否する。ルールの Emulator テストを `firebase-demo` に追加し、合格してからゲームへ組み込んだ（[firebase-demo ADR-0002](../../../firebase-demo/docs/adr/0002-auth-db-development-workflow.md) の手順）。
- ゲーム側の挙動:
  - 起動時、ログイン済みでクラウドに保存があれば、その一覧を端末側にも反映する（クラウドを正とする）。
  - 保存・削除のたびに端末へ保存し、ログイン中はクラウドへも同じ一覧を保存する（未ログイン時は端末のみで、戻り値は失敗扱いにしない）。
  - コース保存のために追加のログイン確認は出さない。ランキング記録の確認フロー（共通ADR-0016）とは独立に、静かに同期する。

## 理由
- 端末を変えても自分のコースで遊べることが、「作る」遊びの継続につながる。
- 地図記号クイズの学習記録（`users/{uid}/mapSymbolProgress/progress`）と同じ「ユーザーごとの1文書」パターンに揃えることで、ルールと実装の前例を再利用できる。
- 一覧を丸ごと保存する方式は、コースが最大6件・1件約100文字と小さいため十分に安く、競合の心配もほぼない（同じアカウントで複数端末から同時に編集した場合は後勝ち）。

## トレードオフ
- 同時編集は後勝ちで、先に保存した変更が消えることがある。低学年向けの個人利用では許容し、競合解決 UI は持たない。
- グリッド文字列の細かい形式（12×8・数字0〜4）はクライアント側の検証が正とし、ルールでは長さと型のみを検証する。
