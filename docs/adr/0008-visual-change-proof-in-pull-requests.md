# ADR-0008: デザイン変更時のPRスクリーンショット証跡

## ステータス
承認済み

## 日付
2026-10-04

## コンテキスト
HTML/CSSの変更はDOMやコードの差分だけでは画面上の効果や予期しない崩れを把握しにくい。レビュー担当者が変更内容を視覚的に比較できる証跡がPull Requestに必要である。

## 決定
- ユーザー向けのレイアウト、スタイル、画像表示に影響する変更を含むPull Requestには、「画面確認」セクションを設け、変更前後を比較できるスクリーンショットをPR本文に添付する。
- 変更前・変更後の画像には対象画面とビューポート（例：スマートフォン幅・デスクトップ幅）が分かるラベルを付け、比較対象の条件を揃える。
- レイアウト変更が影響する主要な画面サイズを確認し、PR本文のチェックリストに確認した幅と表示上の要点を記録する。
- スクリーンショットはGitHubのPull Requestコメントへ添付し、生成画像ファイルはリポジトリに追加しない。PRコメントに画面確認の条件と結果を残す。
- PRコメントへ添付できない場合は、画像ファイルをリポジトリへ保存せず、添付できない理由と確認結果をコメントに明記する。

## ローカル確認手順

1. リポジトリのルートでローカルサーバーを起動する。
   `python3 -m http.server 8765 --bind 127.0.0.1`
2. 対象ページをブラウザで開き、データ取得・画像読み込み・画面描画が完了するまで待つ。読み込み中の文言や未ロード画像が残った状態では撮影しない。
3. デスクトップ幅と、必要に応じて主要なモバイル幅で表示を確認する。
4. 完全描画後のスクリーンショットを取得し、PR本文またはコメントの「画面確認」セクションに添付する。
5. 認証や外部データが必要な画面では、未認証・認証済みなどの確認条件をPRに明記する。確認できない状態を成功例として掲載しない。

## 理由
- レビュー時に変更前後の差分と意図した見た目を迅速に判断できる。
- デスクトップでは問題が見えにくいモバイル固有の崩れなどを、変更と一緒に検証できる。
- スクリーンショットはPRコメントのレビュー証跡として保持し、ソース管理へ不要な画像ファイルを増やさない。

## トレードオフ
- 画面変更ごとに複数サイズの撮影とPRへの添付が必要になり、レビュー準備に追加の手間がかかる。
- スクリーンショットは撮影時点の状態であり、実機やすべてのブラウザー環境の完全な再現を保証するものではない。
