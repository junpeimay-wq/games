# ADR-0017: タッチ操作UIの表示は入力手段で決める

## ステータス
承認済み

## 日付
2026-11-15

## コンテキスト
レトロ格闘ファイトでは、タッチパッド（`#pad`）の表示をビューポート幅で切り替えていた（`@media (min-width: 721px)` で非表示）。そのため、画面幅が721px以上のタブレットではタッチボタンが表示されず、キーボードもないためプレイできない状態だった。

画面の広さと入力手段は無関係である。大きな画面のタッチ端末（タブレット）もあれば、幅の狭いウィンドウでもマウスで操作する環境もある。幅による判定はどちらのケースでも誤判定しうる。

## 決定
- 全ゲーム共通の方針として、タッチ操作UI（オンスクリーンのボタン類）の表示・非表示は、画面幅ではなく入力手段の能力で決める。主判定には CSS の `pointer` メディアクエリ（`pointer: coarse` / `pointer: fine`）を使い、必要に応じて JavaScript のタッチ検出（`'ontouchstart' in window`、`navigator.maxTouchPoints > 0`）をフォールバックとして併用する。
- ビューポート幅のみを根拠にタッチ操作UIを隠してはならない。幅のメディアクエリはレイアウト調整（余白、文字サイズ、配置など）には引き続き使ってよい。
- レトロ格闘ファイトの `#pad` はこの方針で実装する。主ポインタが `fine` の端末では CSS で隠し、JavaScript がタッチ対応を検出した場合は `body.touch-capable` クラスで表示を強制する（フォールバックを優先する）。

## 理由
- `pointer` メディアクエリは端末の主たる入力手段を直接表すため、画面幅から端末の種類を推測するより正確に判定できる。
- JavaScript のタッチ検出を重ねることで、ポインタ種別の申告が実態と異なる端末でも、ボタンが消えてプレイできなくなる事故を表示側に倒して防げる。

## トレードオフ
- マウスのみのPCではタッチパッドは引き続き表示されない。キーボード操作が前提であり、これは従来どおりの挙動である。
- タッチ対応ノートPCでは、タッチ検出によりパッドが表示される。キーボードがあるため不要な場合もあるが、操作手段が増えるだけでプレイの妨げにはならないため、この挙動を許容する。
- `pointer` メディアクエリに未対応の古いブラウザでは、タッチ検出が効かない場合にパッドが常時表示される。表示側に倒れるため、プレイ不能にはならない。

## 関連
- レトロ格闘ファイトのタッチパッド実装（`retro-fight/style.css`、`retro-fight/game.js`）。
- 他ゲームの監査結果（2026-11-15）。snake の方向パッドは常時表示で幅による非表示はなく、tictactoe、block-puzzle、terrain-quest にも幅や端末種別で必須の操作UIを隠す実装はなかったため、本決定に伴う変更はレトロ格闘ファイトのみ。
