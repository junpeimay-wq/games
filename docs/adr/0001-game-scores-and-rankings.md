# ADR-0001: Google認証を用いたゲーム別ハイスコアとランキング

## ステータス
承認済み

## 日付
2026-10-03

## コンテキスト
各ゲームのスコアは現在IndexedDBなどで端末内に保存され、プレイヤー間で共有するランキングはない。Firebase AuthenticationとFirestoreを使う `firebase-demo` を先行実装として、各ゲームに安全で一貫したランキング機能を展開する。

## 決定
- 認証・DB連携は [ADR-0002](../../firebase-demo/docs/adr/0002-auth-db-development-workflow.md) に従い、まず `firebase-demo` で実装とテストを完了してから各ゲームに展開する。
- ランキングへの投稿にはGoogle認証を必須とする。未認証プレイヤーにはスコア保存にGoogle認証が必要であることと認証導線を表示する。スコアはゲームから自動送信し、手入力させない。
- ゲーム終了時にハイスコアを更新した場合だけランキング投稿の対象とする。すでに認証済みなら追加の確認を繰り返さずに自動記録する。
- 未認証時にハイスコアを更新した場合は、Google認証が必要であることを示した上で、ランキングに保存するかを確認する。同意して認証に成功した場合は、そのハイスコアを自動送信する。スコアの手入力は求めない。
- Firestoreにはユーザー・ゲームごとに1件のハイスコアを保持し、同じユーザー自身がより高いスコアを出した場合だけ更新する。
- スコアデータの更新日時にはサーバー時刻を使う。
- `snake` のスコアはゲームが算出した得点、`block-puzzle` のスコアはゲームが算出した得点とする。
- `tictactoe` は1ゲームの得点ではなく、プレイヤーの連勝数をスコアとする。勝利で連勝数を増やし、敗北または引き分けで連勝数をリセットする。
- 採点基準が異なるため、ゲーム間の合計スコアや総合ランキングは設けない。ランキングはゲームごとに分ける。
- ゲーム別ランキングを表示する専用の `ranking/` ディレクトリとページを用意する。各ゲームからランキングへ移動でき、ランキングページから各ゲームへ戻れるようにする。
- 各ゲームのハイスコア更新判定と既存のローカル記録を維持し、クラウド記録の失敗でゲーム進行を妨げない。

## 理由
- Google認証で投稿者を識別し、Firestoreルールで他人のUIDを使った投稿や許可されないデータを拒否できる。
- ゲーム内のスコアを自動送信することで、入力間違いを避け、ランキング値とプレイ結果の対応を保てる。
- ゲームごとのランキングなら、異なる採点尺度を不自然に合算せず公平な比較ができる。
- 共通デモで先行検証することで、各ゲームへの展開前に認証・DB・ルールの回帰を検出しやすい。

## トレードオフ
- Google認証しないプレイヤーのスコアはオンラインランキングに投稿できない。
- クライアントから届くスコアは改ざん可能なため、認証とルール検証だけでは正当なゲームプレイの証明にならない。
- `tictactoe` の連勝数は連続した対戦結果に依存するため、勝敗・引き分けの終了処理とリセット挙動を明確にテストする必要がある。
