# ADR-0004: ランキングへのプレイヤー画像表示

## ステータス
承認済み

## 日付
2026-10-03

## コンテキスト
ランキングデータにはGoogleアカウントから取得した `photoURL` が保存されているが、ランキング画面には表示されておらず、プレイヤーを視覚的に識別できない。

## 決定
- `ranking/` のTop 3・Top 10とFirebaseデモのランキング行に、スコアデータの `photoURL` をサムネイル表示する。
- 画像URLはHTTPSの場合だけ読み込む。Googleプロフィール画像との互換性を優先し、`no-referrer`を明示せず、ブラウザ標準のリファラーポリシーを使用する。
- URLがない場合や画像の読み込みに失敗した場合は、共通のプレースホルダーを表示する。画像の失敗でランキングデータや順位表示は妨げない。
- 認証状態が確定した時点で、保存済みの各ゲームのランキング記録に現在のGoogleプロフィール名・画像URLを反映する。スコア自体が更新されない場合もプロフィールだけを更新する。
- Googleプロフィール名・画像URLの正本は `users/{uid}` に保存する。`scores` のプロフィール情報はランキング取得を効率化するための表示用スナップショットとして扱う。
- Googleログイン時の画像URLは、Firebase Authの統合 `user.photoURL` よりも、Googleプロバイダーの `providerData` に含まれる最新の `photoURL` を優先する。統合プロフィールが古いURLを保持していても、Google側の最新画像を保存・表示する。
- プロフィール同期は本人の記録に限り許可し、スコアを下げる更新は引き続き拒否する。

## 理由
- 既存のGoogleプロフィール画像を活用し、ランキング上のプレイヤーを見分けやすくする。
- HTTPSに限定し、壊れた画像や安全でないプロトコルに対して安定した表示を保つ。
- Google画像配信元がリファラー条件を変更しても、明示的な`no-referrer`指定によって画像表示を妨げない。

## トレードオフ
- プロフィール画像はFirebase外のGoogle画像配信元へ追加リクエストを発生させる。
- ユーザーがGoogleプロフィール画像を変更した場合、次回の認証状態確定時にFirestoreの保存値を更新する。
- ブラウザや拡張機能の追跡防止設定によって外部画像が読み込めない場合は、プレースホルダー表示になる。
