# ADR-0001: レトロ格闘ファイトの基本ルールと連勝数スコアの定義

## ステータス
承認済み

## 日付
2026-11-14

## コンテキスト
GAME ARCADEに、ドット絵風の対戦格闘ゲームを新しく追加する。アーケードの他ゲームと同様に、スコアの定義とランキング連携の方法を先に定めてから実装する必要がある。

## 決定
- `retro-fight/` はプレイヤー対CPUの1対1格闘ゲームとする。体力を0にするか、制限時間60秒の終了時に体力が多かった側がラウンドを取り、2ラウンド先取で試合勝利とする。
- 操作は移動・ジャンプ・ガード・パンチ・キックとする。パンチは発生が速く低威力、キックはリーチが長く高威力だが隙が大きい。ガード中はダメージを軽減する。キーボードとスマートフォン向けタッチボタンの両方に対応する。
- スコアは1試合ごとの得点ではなく、試合の連勝数とする。勝利で連勝数を増やし、敗北でリセットする（戦略的〇×ゲームと同じ方式）。
- ランキング連携は共通基盤（`firebase-demo/score-service.js`）を使い、[共通ADR-0001](../../../docs/adr/0001-game-scores-and-rankings.md) に従う。自己ベストを更新したときだけ、認証済みなら自動記録し、未認証なら認証して記録するかを確認する。スコアの手入力はさせない。
- 自己ベストは端末の `localStorage` にも保存し、Googleログイン済みの場合は起動時にクラウドの自己ベストを優先して反映する（[共通ADR-0013](../../../docs/adr/0013-authenticated-score-sync.md)）。
- ゲーム固有の連勝遷移は `firebase-demo/score-utils.js` の `nextRetroFightStreak` に置き、単体テストで検証する。Firestoreの許可ゲームへの `retro-fight` 追加はルール変更として、firebase-demoのEmulatorテストで検証してから展開する（[firebase-demo ADR-0002](../../../firebase-demo/docs/adr/0002-auth-db-development-workflow.md)）。

## 理由
- 格闘ゲームは試合単位で勝敗が完結するため、連勝数が腕前の指標として分かりやすく、既存の連勝ランキングとも形式を揃えられる。
- 共通基盤を使うことで、認証・同意確認・プロフィール同期などの挙動が他ゲームと一致し、ゲームごとに実装がばらつかない。

## トレードオフ
- 連勝数は対戦相手（CPU）の強さに依存するため、CPUの強さを変更すると過去の記録と単純比較できなくなる。
- クライアントから送信される連勝数は改ざん可能であり、認証とルール検証だけでは正当なプレイの証明にならない（共通ADR-0001と同じ前提）。
